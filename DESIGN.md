# 1Tool design

> **Latest user requirements:** Use colorful sidebar icons, an accent-filled selection row with white text, and a single logo without a wordmark in the top-left corner. Support a persistent global Liquid Glass option across appropriate native application surfaces. These requirements override conflicting reference-image details and older visual rules below; see [the current design directive](docs/DESIGN-DIRECTION-2026.md).

> **Selected reference:** The user's [macOS 27 Figma component library](https://www.figma.com/design/etVh0P2oCtaLiF3XXQUqYz/macOS-27--Community-?node-id=121-18094) and supplied default-window screenshot are the concrete visual baseline. Use restrained native default components, and review the complete component library before inventing component styling. See the latest supplement in [the current design directive](docs/DESIGN-DIRECTION-2026.md).

> **2026-10-23 design direction update:** The user's latest instruction is to redesign the entire interface using current macOS Liquid Glass design and WWDC 2026 Apple Design Award references, with no dependency on existing layouts. [The current design directive](docs/DESIGN-DIRECTION-2026.md) supersedes the visual layout, opacity, typography, spacing and fixed-size rules below wherever they conflict. Existing functional and data-protection requirements remain applicable.

Current redesign: a native utility workspace, including Storage Cleanup and About, and a compact status panel for frequent controls. The selected visual reference is the user-provided macOS default-window example; Figma component metadata remains unavailable and is not claimed as measured.

Use system typography, semantic content surfaces and native NavigationSplitView with a scrollable sidebar. A persistent Liquid Glass preference controls navigation/action materials and the quick panel. macOS 26+ uses glassEffect and glass button styles; macOS 14–25 use standard material fallbacks. Reduce Transparency and Increased Contrast take priority and use opaque surfaces. Reading groups and charts keep standard content materials.

Default accent: system blue. Offer system, blue, purple, pink, red, orange, yellow, green and graphite. Default blue uses unmodified macOS systemBlue. Native tint drives controls; ordinary text retains semantic foreground contrast. Theme and accent update the main window and status panel and persist independently. General settings start with a language selector, followed by three selectable miniature window previews and a color row, matching macOS Settings conventions.

Brand: an original single white upright open-jaw wrench on a flat solid-blue rounded-square app icon. No gradients, gloss or drawn shadows. Tools/Icon.swift deterministically draws this original vector artwork; the menu bar and default logo use the same silhouette as a monochrome template. The menu bar offers the original wrench plus 31 curated symbols in four rows of eight. Normalize visible ink to at most 20×18 points on a 22×22-point canvas, reject marks thinner than 8 points or shorter than 14 points, and let AppKit size the square status item. The default wrench has 1×/2× artwork; active keep-awake sessions tint the entire mark green without a dot. Retired, ambiguous presets return to the default wrench on upgrade. Follow Apple's [menu bar guidance](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar).

Default window 920×760; minimum window 880×660; detail pages scroll. Status panel measures its content and adapts height to the number of displays, keyboard support, errors and timer state. It scrolls only when it exceeds the current screen’s available height. Keep its 365-point width stable and use the global glass/material preference while preserving readable text. Left click opens it; right click opens a native keep-awake/duration/settings/quit menu.

Layout is centralized in `Appearance.swift`: 24-point page inset, 20-point section gap, 16-point group padding, 12-point row gap and 10-point content-group corners. Detail content is bounded to 920 points including page padding; action bars share that exact boundary. Native navigation titles replace the large duplicate heading. Sidebar width is user-resizable from 190 to 280 points, initially 220. These are implementation values, not asserted Figma measurements.

The quick panel uses one native nonactivating NSPanel with a single pointer-and-body glass/material shape. Close on outside click or Escape; its gear opens Appearance. All Settings menu entries and the keyboard shortcut use that same destination. Timers are 30 minutes, 1/2/4/8 hours and ∞; all three entry points share these choices.

Top-left branding is one centered 48-point Logo. Sidebar icons follow the user's Apple Settings reference: a 20-point solid per-feature color tile with 5-point continuous corners and a centered white 13-point symbol. Tile colors use a fixed sRGB palette so dark appearance does not turn white-on-color artwork into neon foreground colors. These dimensions are implementation choices, not user-specified measurements. All navigation tiles use color, including Appearance; keep them opaque when the window is inactive. Selected rows use the current accent as a solid background and white text, following the user's latest light/dark Apple Settings screenshots. Disable native List row selection to prevent a second selection layer; retain keyboard navigation and accessible buttons. Detail scrolling restarts at the top after page changes. Appearance, Permissions and About form the final navigation group. The quick panel contains only awake, display and keyboard controls; Quit remains in the full settings/native menu.

Localization: English development language; eight complete localizations in native String Catalogs. Follow System by default, or select a language by its native name. Apply changes to the settings root and separately hosted panel immediately, and publish the resolved code to Finder over existing configuration IPC. Keep user-defined names and system-provided app/input-source names intact. Preserve all existing configuration when migrating the legacy Chinese-only preference. Text wraps vertically, sidebar labels have full-value tooltips, and appearance labels use a 96-point column for longer translations.

Application presence: run as a menu bar accessory, with no Dock icon or app-switcher entry. Settings remain available from the status panel and right-click menu; closing the settings window keeps the service running.

Keep Awake: the menu bar remains the primary shortcut; the sidebar has no running-session footer. Its panel offers one toggle and one duration picker, shared with the settings page; the right-click menu offers Start/Stop and a checked duration submenu. While running, call the submenu Change Duration rather than Keep Awake For. Changing the duration restarts timing from now; remember the selected duration for the next manual start. Keep all six presets and indefinite sessions. The settings page shows current state, duration and Keep Display On; automatic power rules and advanced sleep options are collapsed by default. Preserve all underlying options and preferences. Remove redundant status/menu-icon shortcuts from these surfaces.


Menus use native button menus within a shared trailing frame. Their visible right edges align with switches and buttons, and tooltips expose the full value. Hardware-capable displays do not show a redundant software-dimming checkbox. A software-only display offers a hardware retry action. Input sources show the default and per-app rules, without the redundant current-source row.

Cleanup: a subdued ring for volume usage with an accent slice for estimated reclaimable bytes; a short horizontal ranking of the largest cache sources; app groups with tri-state selection, per-directory controls and optional detail. No default selection. Keep selected capacity and cleanup action in a fixed bottom bar. See docs/CLEANUP.md for operational semantics.

App Uninstaller: installed-app search leads to an explicit file preview. Select only the program bundle by default; related app data is opt-in. Label weaker app-name matches. Keep capacity and the uninstall action in a fixed bottom bar, confirm every path in a modal sheet, and report recoverable partial results. Preserve system apps and shared data. See docs/UNINSTALL.md for discovery, protection and recovery boundaries.

Permissions: query Automation per target without prompting during refresh; request only after a user action. Show actual Finder extension and login approval status. Full Disk Access has no reliable app-wide query: link to System Settings and retain concrete inaccessible paths in cleanup/uninstall. Distinguish file ownership, CLI administrator interaction and hardware failures. Returning to the app refreshes states without starting destructive work.

System Appearance controls the real macOS light/dark/automatic policy. Main window and quick panel inherit system appearance; app-local scheme preferences are retired without writing the OS at startup. App accent and Liquid Glass remain application-specific. See `docs/SYSTEM-APPEARANCE.md` for runtime compatibility and native evidence. Custom bright accents use a white-text-safe selection fill in either appearance; default blue retains the native color.
