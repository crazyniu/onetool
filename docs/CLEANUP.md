# 垃圾清理

清理页先扫描、再由用户选择应用和缓存目录，默认没有任何勾选。环形图展示当前卷的磁盘占用，百分比保留一位小数，页面可见时每五秒重新读取容量。条形图展示已扫描位置实际缓存占用最大的五个应用，包含近期和受保护文件；各应用另列当前符合清理条件的容量。统计来自文件实际分配块数，不能把缓存总占用等同于可删除量。APFS 快照、克隆和其他应用活动会影响最终释放空间，因此图表是估算，完成后另显示磁盘可用空间的实际变化。

首次打开页面自动进行只读扫描；重新扫描会重新枚举文件并更新占用。清理结束后自动重扫并保留操作结果，从而呈现未清理和重新生成的缓存。返回前台时，扫描超过一分钟且没有勾选或待查看的操作结果，才自动刷新缓存清单，避免替换用户正在检查的选择。

## 目前覆盖的范围

- Chrome / Chrome Canary 的 Profile 与 Default 网络、代码缓存；Codex 对应的缓存目录。
- Notion、Visual Studio Code、orca 的 Cache、Code Cache 和 GPUCache。
- pip、Homebrew、Electron 下载缓存，npm `_cacache` 和 Cargo registry 压缩包。
- Xcode 与系统 clang 的 ModuleCache。
- Codex、Notion 的日志和系统 DiagnosticReports。

应用缓存至少闲置一天，开发缓存七天，日志三十天。这里的闲置判断使用最后修改时间，并另外检查当前打开的文件；不会仅凭文件夹名称就删除整个目录。每个来源最多检查 150,000 个目录项，超过或无权访问时会标明部分文件无法检查。无法枚举的位置与受阻子目录会保留路径，并标记扫描未完整完成；可进入权限管理查看适用的访问设置。扫描范围仍是已知缓存规则，不是全盘占用统计。

## 用户决定删除谁的文件

每个应用分别显示已扫描占用、可清理容量及缓存目录数量。点击应用左侧复选框可选中该应用全部可清理目录，也可展开应用分别勾选目录；部分选择显示减号。详情展示路径、可清理和受保护的文件数，以及最多十二个文件样例，完整目录可在 Finder 中查看。按来源类型筛选不会清除其他类型的选择；固定底栏始终显示全部已选目录和容量。

默认「移到废纸篓」：被选中的文件按原相对目录移入独立恢复文件夹，附带 `1Tool-Recovery.json` 原路径清单，再调用 macOS 废纸篓 API。如果无法移到废纸篓，文件仍留在 `~/Library/Application Support/1Tool/Cleanup Recovery`，结果页会给出位置。关闭所属应用后，可按清单恢复缺失文件；不要覆盖应用后来生成的文件。只有清空废纸篓才释放其占用，本程序不会代用户清空废纸篓。

「永久删除」默认关闭，启用后仍需在确认窗口逐项核对应用名称、完整目录、文件数与容量。确认使用稳定的选择快照，后续界面选择不会扩展操作范围。文件只按扫描快照中的精确路径逐个删除；不使用递归 shell 删除。扫描不会退出任何应用，也不会调用 sudo。

## 文件保护

- 已知运行中的所属应用只统计缓存占用，不产生可清理候选；每次清理重新获取应用和打开文件列表。无法取得打开文件列表时停止操作。
- 路径中的软链接、非本人文件、硬链接、特殊文件、近期文件与打开的文件跳过。
- 清理前再次核对设备、inode、大小、修改时间、文件类型、所有者和硬链接数。目录链通过 `openat` 和 `O_NOFOLLOW` 打开，删除或移动锚定已验证目录。
- 不扫描文档、聊天历史、Cookie、会话、设置、应用安装目录、更新暂存目录、任意 Git 工作区或普通 `node_modules`。
- 不自动清理 Bun / uv 共享包缓存、npm 隐藏安装残留或旧应用安装目录。这些需要额外工具和使用关系验证，不能用本次有限缓存规则代替。

应用仍可能在检查后开始使用文件，因此应先关闭正在开发或下载的任务，确认目录用途后选择清理。可恢复模式提供回退；它不是完整磁盘备份。

## 设计参考

参考 [Mole 的保护边界](https://github.com/tw93/Mole/blob/main/SECURITY.md) 与 [PureMac](https://github.com/momenbasel/PureMac) 的预览、用户选择和恢复思路。实现为独立 Swift 代码，没有复制其清理脚本。测试使用隔离临时目录，覆盖旧文件、近期文件、占用、运行中应用、软/硬链接、扫描后变更、路径替换、越界路径、取消和真实回收恢复。

## 结果与取消

结果分别显示完成、部分完成、取消或失败，列出已处理、跳过和未处理的文件数，以及所有恢复位置。错误直接显示，不以成功勾号掩盖零处理失败。扫描取消后需要重新扫描；清理取消只停止后续文件，已移动的文件仍可通过结果中的恢复位置找回。当前分类无结果时可清除筛选，不会被描述成全盘已经清理干净。

## 容量刷新

磁盘总量和可用容量使用同一次新查询，清除 URL 资源缓存。环图已用百分比保留一位小数；读取失败显示未知，页面打开期间每五秒刷新磁盘容量。进入清理页时在无选择、无清理结果状态下自动扫描，前台恢复且扫描超过一分钟时按相同条件刷新；手动重扫清空旧选择。已有选择不会被后台刷新扩展。清理完成后自动重扫，同时保留处理结果。

占用图是已知缓存位置的快照，受限位置保留扫描不完整提示；它不代表全盘或所有应用缓存。重新扫描不改变文件时，容量可以保持一致。磁盘百分比和缓存大小采用不同分母；小规模缓存清理不一定改变一位小数的磁盘百分比，移到废纸篓也不会立即释放磁盘空间。
