# 应用卸载

“应用卸载”页扫描 `/Applications` 和 `~/Applications`（最多三层目录，不进入程序包）。支持搜索名称或 bundle ID；其他位置的应用通过“添加应用”选择。选中应用后异步读取程序包与当前用户 Library 中的关联文件，显示路径、类型及实际分配空间估算。

默认只选中应用本体。关联数据由用户逐项勾选，可能包含偏好、会话、登录信息、历史记录或保存的工作；确认窗口列出所有所选路径及总容量，确认后才执行。运行中的应用不会被自动强制退出。

## 识别范围

- 精确 bundle ID：Application Support、Caches、Logs、WebKit、HTTPStorages、Containers。
- 精确文件名：Preferences 下的 `<bundleID>.plist`，Saved Application State 下的 `<bundleID>.savedState`，HTTPStorages 下的 `<bundleID>.binarycookies`。
- Application Support、Caches、Logs 中与应用显示名或程序包名称完全一致的目录，单独标记“根据应用名称匹配”。名称可能不是唯一的所有权证据，需用户核对；已知其他应用同名时排除。
- 另有相同 bundle ID 的已安装副本时，只允许移除选定程序包，共用数据受到保护。执行前重新扫描应用目录检查新副本。

本功能不会声称找到全部残留。共享 Group Containers、厂商目录、名称前缀或模糊匹配、系统级 `/Library`、启动项、特权辅助程序、收据、驱动和内核扩展均不清理。含服务或驱动的软件应使用厂商卸载器。无权访问或超过每条路径 200,000 个目录项的结果显示为不可选，不视为零字节；数据大小是估算，APFS 克隆、压缩和硬链接可能影响统计。

## 保护与恢复

系统应用（包括 `com.apple.*`）、1Tool 自身、嵌套应用及用户 Library/废纸篓中的应用受保护。程序包必须有有效 bundle ID 和 `APPL` 类型。根路径或祖先包含软链接时拒绝操作。程序包内部的软链接作为链接本身移动，扫描不跟随到目标。

执行前检查当前运行的 bundle ID、应用路径及当前用户打开的文件；每个项目移动前再次检查。无法获得进程/打开文件信息时停止。扫描快照记录全部目录项的设备、inode、类型、大小、修改时间和变更时间，移动前逐项重新比较，变化的项目拒绝移动。文件操作使用不跟随软链接的父目录描述符与排他性 rename，不运行 shell 删除，不使用 sudo。

应用本体先移动；其移动失败时保留全部数据。其他项目失败或取消时报告已移动与未移动的路径，允许部分完成。应用仍可能在最终检查后重新启动或更改文件；应先退出相关程序再操作。

所选文件先移入独立的 `~/Library/Application Support/1Tool/Uninstall Recovery/1Tool-Uninstall-<UUID>` 文件夹，附带 `1Tool-Uninstall-Recovery.json`，再使用 macOS 废纸篓 API 移动整个恢复文件夹。废纸篓操作失败时保留恢复目录并显示位置。清单记录每个所选项目的原路径及恢复目录中的名称；部分失败时只有存在的项目实际移动成功。

恢复时先退出应用，根据清单将文件移回原路径；仅恢复到缺失目标，不覆盖后来生成的文件。只有清空废纸篓才释放空间，1Tool 不会自动清空废纸篓，也不提供永久卸载模式。

## 参考与验证

参考 [PureMac](https://github.com/momenbasel/PureMac) 的应用关联文件预览和废纸篓卸载流程，实现为独立 Swift 代码。

`Tests/UninstallChecks.swift` 使用隔离程序包与用户目录，覆盖应用发现、精确匹配、名称提示、运行进程/打开文件保护、检查失败、取消、扫描后变化、本体失败保留数据、仅卸载程序包、完整卸载、恢复清单、副本保护、软链接和系统/自身保护。测试只移动自身创建的测试文件，并只清除对应的 UUID 恢复目录。

实际构建、回归测试、原生窗口回收与恢复证据及未运行项目见 [卸载验证记录](UNINSTALL-VALIDATION.md)。

## 扫描受阻与权限入口

已知系统/自身保护直接显示原因，不扫描程序包，也不选中本体。搜索无匹配时显示“清除搜索”；空库存、未加载及未能完整读取应用目录分别显示对应状态。

扫描结果保留受阻项目及具体失败目录，区分访问被拒绝、软链接保护、扫描超限、文件变化/消失、不支持的文件类型及其他读取错误；不可读应用目录不会被当作空库存。错误详情保留系统错误域、代码和原始说明。权限受阻通过共享“权限管理”入口处理，访问被拒绝本身不能判断完全磁盘访问是否已授予，也不会自动申请额外权限。

返回后由用户手动“重新扫描应用”；重新扫描清除旧问题并重新核对文件，关联数据仍默认不选。受阻目录没有可确认快照时不可勾选；其余已检查项目可单独选择，页面明确说明当前清单不完整。执行前如果应用库存无法完整复核，暂停含关联数据的卸载，保留文件与原因。

操作栏使用统一 `ToolActionBar()`，沿用主窗口的正文最大宽度、边距、系统材质与玻璃偏好。

## 运行状态与资源引用

“应用正在运行”和“文件被占用”分别判断。运行状态核对 bundle ID、程序包路径及真实进程可执行文件路径，包含程序包内部的后台辅助进程。lsof 使用 NUL 分隔字段，保留持有进程、PID、描述符、访问模式及完整文件路径。

已核实可执行路径的外部进程对程序包资源的只读/代码映射引用，不代表该应用正在运行，允许继续可恢复的程序包移动。通知中心可能在应用未启动时保留其 `InfoPlist.strings` 映射；Finder 等系统组件也可能持有图标或元数据。

程序包内的实际可执行进程、写入句柄、不能确认的访问模式继续阻止卸载。关联数据即使仅被读取也继续保护。被文件占用阻止时，界面显示具体文件、持有进程及 PID，不再一概要求退出目标应用。程序不会自动结束这些进程。
